# Implementation Plan: Agent Harness for the Agentic Pipeline

## Objective

Build the harness first: every pipeline stage gets a file-based contract (input, output, machine check)
so code can chain the stages later. Claude Code is run manually today; the first target is Claude
reading a requirement and writing the implementation plan headlessly.

## Target Pipeline

```
Requirement ─► [1] Claude: analyse → implementation plan
            ─► [2] OpenAI reviews the plan (once)
            ─► Claude revises the plan from the findings
            ─► [3] Human reviews the final plan (sets Status: Approved)
            ─► [4] Claude implements
            ─► [5] OpenAI reviews the generated code
            ─► Claude revises the code from the findings
            ─► [6] Human reviews the final code
            ─► [7] Execute → on failure: locator self-healing, otherwise collect failure info
```

## Decisions (2026-11-07)

| Topic | Decision |
|---|---|
| Requirement source | Markdown files in `requirements/` in the repo; may be generated by Copilot Chat with MCP, so the format must be tool-agnostic and machine-checked |
| Human gate | `Status:` line in the plan file, edited by the human to `Approved` (simple first; PR-based gate may come later) |
| After OpenAI review | Claude revises the plan/code from the findings and records how each was handled; the human reviews the final version |
| Self-fix at execution | Existing locator self-healing only; a plan to improve self-fix comes later |

## Slice A — Stages 1–3 (requirement → plan → OpenAI review → revision → human)

- **A1 Contracts (done):** requirement template, plan template with `Status` lifecycle, `requirement-check` and `plan-check` scripts.
- **A2 `/write-plan` skill (done):** requirement → plan following the template; reuse-first exploration; Playwright MCP snapshot allowed for roles/labels; no code edits.
- **A3 `ai/review.ts` upgrade (done):** one-pass plan review, output `implementation-review/<plan>.plan.json|md` (schema in
  `ai/ReviewSchema.ts`): verdict `APPROVE | APPROVE_WITH_CHANGES | REJECT`, findings `F<n>` (`REQUIRED_FIX | RECOMMENDED |
  VERIFICATION`, severity, file, problem, action, requirement ids); remains a standalone tool. `--mode code` comes in B3.
- **A4 Revision + runner (done):** `/revise-plan` step that answers every finding (accepted / rejected + reason) in `## Review Resolution`;
  `yarn agent:plan requirements/<file>.md` = `claude -p` (/write-plan) → plan-check → review.ts → `claude -p` (/revise-plan) → plan-check →
  `Status: Awaiting Human Review`, then stop. CLI via child process (no new dependency).

## Slice B — Stages 4–6 (implement → OpenAI code review → revision → human)

Detailed plan: `implementation-plans/harness-b-implement.md`. Gates: `tsc`, `arch-check`, `scope-check`, `--list`,
the plan's specs. Code stays uncommitted until the human sets `Accepted`.

- **B1 Guardrails and checks (done):** `harness:check-arch` (CLAUDE.md rules, baseline for existing violations),
  `harness:check-scope` (diff ⊆ Relevant Files), PreToolUse hook (`.env*`, `.auth/` blocked; self-healing pipeline files ask).
- **B2 `/implement-plan` (done):** implements an `Approved` plan, runs the gates and its specs only through
  `yarn harness:run-tests` (`SELF_HEALING_DISABLED=true`, results in `harness-results/tests/`), at most 3 fix rounds,
  `## Implementation Notes`, sets `Implemented`.
- **B3 `ai/review.ts --mode code` (done):** plan + requirement + rules + diff (`HEAD` + working tree, or `--base`) +
  changed files + cited test results; findings `C<n>` in `implementation-review/<plan>.code.json|md`; `plan-check`
  requires `## Code Review Resolution` from `Awaiting Human Code Review` on. Does not edit the plan.
- **B4 `/revise-code` + runner (done):** the runner sets `Code Reviewed` after `ai:review --mode code` succeeds;
  `/revise-code` answers every `C<n>` in `## Code Review Resolution`, re-runs the gates, sets
  `Awaiting Human Code Review`; `yarn agent:implement` (`--revise` for `Code Changes Requested`), `yarn agent:accept`
  (requires `Accepted`, re-runs the gates, commits on `main`, no push).

## Slice C — Stage 7 (execute) (done, `harness-c-execute.md`)

Summary reporter (`harness-results/summary.json`), `harness:clean`, Winston timestamps + step logs,
`/debug-failure` JSON failure report, `yarn agent:execute <topic>`. Self-fix = locator self-healing only.

## Slice D — Evals (done, `harness-d-evals.md`)

`harness/evals/` scenarios (skill-trial B1/B2, add-test-data, sample requirement → plan), `yarn harness:eval`.

## Constraints

- No new dependencies without approval; no change to the `HealingEngine` flow.
- Scope: Day25 + common (header, footer, cart, checkout).
- One detailed plan per sub-slice in `implementation-plans/`, approved before implementation; commit on `main`.
