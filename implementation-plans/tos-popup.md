# Implementation Plan: Terms of Service Warning Popup on Checkout

## Objective

Verify that when the user clicks **Checkout** on the Shopping Cart page **without** accepting
the Terms of Service, a warning popup is displayed and the user stays on the cart page.

The check is added as **one extra step** in the two existing checkout specs — no new spec file.

---

## Scenario (new step)

Runs right after `verifyShoppingCart()` and before the existing TOS + Checkout step.

| Step | Action | Expected |
|---|---|---|
| 1 | Verify Terms of Service checkbox state | Unchecked (precondition) |
| 2 | Click **Checkout** without ticking Terms of Service | Warning popup is visible |
| 3 | Verify popup content | Title = `Terms of service`, message = `Please accept the terms of service before the next step.` |
| 4 | Verify navigation | URL is still `/cart` (checkout blocked) |
| 5 | Close the popup | Popup is hidden |

The checkbox is left unchecked, so the next existing step (`selectTOSandCheckoutAsGuest()` /
`selectTOSandCheckoutWithLogin()`) ticks it and continues the checkout as today.

```html
            <span class="ui-button-icon-primary ui-icon ui-icon-closethick"></span>
            <span class="ui-button-text">close</span>
        </button>
    </div>
    <div id="terms-of-service-warning-box" class="ui-dialog-content ui-widget-content">
        <p>Please accept the terms of service before the next step.</p>
    </div>
</div>
```

Locator check against this DOM:

| Plan locator | DOM evidence | Result |
|---|---|---|
| `getByRole("dialog", { name: title })` (title = `Terms of service` from JSON) | `role="dialog"` + `aria-labelledby="ui-id-2"` → `<span id="ui-id-2">Terms of service</span>` | ✓ matches |
| `getByRole("button", { name: "close" })` inside dialog | `<button role="button">` with text `close` (also `title="close"`) | ✓ matches |
| `#terms-of-service-warning-box` | Unique id on the dialog content; `innerText` → message (surrounding whitespace removed by `.trim()`) | ✓ matches |

Notes:
- `ui-id-2` is generated by jQuery UI — **not** used in any locator.
- The dialog has **no** `ui-widget-overlay` (not modal), so it does not block the page; it is still
  closed explicitly to leave the cart in a clean state for the next step.
- Before the dialog opens, `#terms-of-service-warning-box` exists hidden in the page; jQuery UI moves
  it into `.ui-dialog` on open. The message is read only **after** `toBeVisible()` on the dialog,
  so the plain id selector is enough — the earlier `.ui-dialog` prefix is dropped (fewer
  framework-specific classes, id-first as in the healing prompt's locator priority).
- After close, the dialog stays in the DOM with `display: none` → `toBeHidden()` is valid.

## Changes

### 1. UPDATE — `models/components/cart/TotalComponent.ts`

Add one read method so the flow can check the precondition (checkbox unchecked).
It goes through `withHealing()` like the existing `selectTermOfService()` — a broken
`#termsofservice` selector is then healed via the ACTION path. No change to existing methods.

```typescript
public async isTermOfServiceChecked(): Promise<boolean> {
    return await this.withHealing(this.termOfServiceSel, l => l.isChecked());
}
```

### 2. UPDATE — `models/pages/ShoppingCartPage.ts`

No new component: the dialog is small and not reused anywhere, so its locators are declared
directly in the page (CLAUDE.md: "Locators that do not belong to a component are defined in the page").

Source change taken into account: `BasePage` now extends `Component` with `body` as root
(commit `616780e`), so pages inherit `withHealing()`. Per the updated CLAUDE.md, page-level
CSS/XPath interactions must use `this.withHealing(selectorStr, action)` — same pattern as
`RegisterPage.getFirstNameValidationError()` and `CheckoutAsGuestPage.clickOnCheckoutAsGuestBtn()`.

- Locators are class properties, not inline in methods.
- Dialog and close button: `getByRole()` (inherently stable, may `.click()` directly per CLAUDE.md).
- Message (CSS, no role): read through `withHealing()` — resolved under `body`, where jQuery UI
  appends the dialog. On failure, `ComponentFailureCollector` resolves the source via
  `SourceCodeCollector.find("ShoppingCartPage")` → `models/pages/ShoppingCartPage.ts`.

```typescript
export default class ShoppingCartPage extends BasePage {

    private readonly tosWarningMessageSel = "#terms-of-service-warning-box"
    private readonly tosWarningCloseBtnName = "close"

    constructor(page: Page, testInfo: TestInfo) {
        super(page, testInfo)
    }

    // ... existing cartItemRowCompList(), totalComp() unchanged

    public tosWarningDialog(title: string): Locator {
        return this.page.getByRole("dialog", { name: title })
    }

    public async getTosWarningMessage(): Promise<string> {
        return (await this.withHealing(this.tosWarningMessageSel, l => l.innerText())).trim()
    }

    public async closeTosWarningDialog(title: string): Promise<void> {
        await this.tosWarningDialog(title).getByRole("button", { name: this.tosWarningCloseBtnName }).click()
    }
}
```

`tosWarningDialog(title)` returns a `getByRole` locator used only for `toBeVisible()` / `toBeHidden()`.
The dialog title is **not** hardcoded in the page: it is the dialog's accessible name and is passed
in from `TermsOfServiceWarningData.json` by the flow (decision: title comes from test data).
Matching the dialog by its title therefore also asserts the title text — no separate title locator
or title assertion is needed. The close button name `close` is a UI label, not test data, so it stays
a class property.

### 3. NEW — `test-data/checkout/TermsOfServiceWarningData.json`

Expected popup text lives in test data, not in source.


Both values are used by the flow: `title` to locate the dialog (accessible name), `message` for the text assertion.

### 4. UPDATE — `test-flows/computer/OrderTestFlow.ts`

Add one flow method. It calls Page/Component methods only. Visibility and URL use web-first
assertions; text/state values come from `withHealing()`-wrapped methods (same style as
`LoginTestFlow` / `RegisterTestFlow`).

```typescript
import termsOfServiceWarningData from "../../test-data/checkout/TermsOfServiceWarningData.json" assert { type: "json" };

public async checkoutWithoutTOSAndVerifyWarningPopup(): Promise<void> {
    const { title, message } = termsOfServiceWarningData
    const shoppingCartPage: ShoppingCartPage = new ShoppingCartPage(this.page, this.testInfo)
    const totalComp = shoppingCartPage.totalComp()

    expect(await totalComp.isTermOfServiceChecked()).toBe(false)
    await totalComp.clickOnCheckoutBtn()

    await expect(shoppingCartPage.tosWarningDialog(title)).toBeVisible()
    expect(await shoppingCartPage.getTosWarningMessage()).toEqual(message)
    await expect(this.page).toHaveURL(/\/cart$/)

    await shoppingCartPage.closeTosWarningDialog(title)
    await expect(shoppingCartPage.tosWarningDialog(title)).toBeHidden()
}
```

## Decisions

1. **Dialog title source:** from `TermsOfServiceWarningData.json` (`title`), passed to
   `ShoppingCartPage.tosWarningDialog(title)` / `closeTosWarningDialog(title)`. Not hardcoded in the page.
2. **Test data loading:** `import ... assert { type: "json" }` (CLAUDE.md updated).
3. **No new spec / no new component:** step added to both existing specs; dialog locators live in `ShoppingCartPage`.
